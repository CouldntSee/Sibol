## 1. Power & wiring

```text
3.7 V cell ──► TP4056/protection ──► 5 V BOOST ──┬──► ESP32 VIN (5V pin)
                                                  └──► MQ-135 VCC (heater)
3.3 V from ESP32 ─────────────────────────────────────► OLED VCC, soil probe VCC
```

- **Never** put 3.7 V on the ESP32 `3V3` pin. Absolute max is 3.6 V; a full cell is 4.2 V. This destroys the chip.
- **Never** put 3.7 V on `VIN`. The AMS1117 LDO needs ~4.4 V+; at 3.7 V it drops out and the ESP32 browns out during Wi-Fi TX bursts.
- The MQ-135 heater is specified at **5.0 V ±0.1 V**. At 3.7 V its sensitivity drops and readings drift as the cell discharges. The firmware measures the rail and flags this (`V:3.7!` on the OLED, red banner in the app).

### Wiring netlist

| Net | From | To | Note |
|---|---|---|---|
| SDA | OLED SDA | GPIO21 | I²C data |
| SCL | OLED SCL | GPIO22 | I²C clock |
| SOIL_AO | Soil probe AO | GPIO35 | ADC1_CH7, analog in only |
| MQ_AO | MQ-135 AO | 10 kΩ → **GPIO34** → 10 kΩ → GND | Halves 5 V swing; firmware ×2 |
| BAT_SNS | Cell + | 10 kΩ → **GPIO33** → 10 kΩ → GND | ×2 in firmware |
| RAIL_SNS | Boost 5 V out | 10 kΩ → **GPIO32** → 10 kΩ → GND | ×2 in firmware |
| MQ_VCC | MQ-135 VCC | Boost 5 V | ~160 mA heater |
| 3V3 | OLED VCC, soil VCC | ESP32 3V3 | 100 nF at each module |
| GND | All grounds | Single star point | One return path |
| LED | Status | GPIO2 (onboard) | Grade / hazard blink |

**ADC notes**

- GPIO32/33/34/35 are **ADC1**. ADC2 pins (0, 2, 4, 12–15, 25–27) stop working while Wi-Fi is active — do not move the sensors there.
- Use **10 kΩ / 10 kΩ** dividers, not 100 kΩ. The ESP32 ADC wants a low source impedance; 100 kΩ dividers read low and settle slowly. Divider drain is ~210 µA, negligible against ~400 mA total.
- Put a **100 nF cap from each ADC pin to GND**. It acts as a charge reservoir for the sample-and-hold.
- 470 µF across the boost output absorbs Wi-Fi TX bursts so the ADC reference does not sag.

## 3. Flash the firmware (Arduino IDE)

**Board package:** `esp32` by Espressif Systems — tested on **3.3.12**
Boards Manager URL: `https://espressif.github.io/arduino-esp32/package_esp32_index.json`

**Libraries** (Library Manager):

- `Adafruit SSD1306`
- `Adafruit GFX Library`
- `Adafruit BusIO` (installed as a dependency)

**Tools settings**

| Setting | Value |
|---|---|
| Board | ESP32 Dev Module |
| Upload Speed | 921600 |
| Flash Frequency | 80 MHz |
| Flash Mode | DIO |
| Flash Size | 4 MB (32 Mb) |
| Partition Scheme | Default 4MB with spiffs |
| Erase All Flash Before Sketch Upload | **Disabled** |
| Port | your CP210x / CH340 port |

**Steps**

1. Open `SIBOL_NODE.ino`, select the board and port.
2. Click **Upload**. If it stalls at `Connecting.....`, hold the **BOOT** button until writing starts.
3. Open **Serial Monitor at 115200**. You will see:

   ```text
   SIBOL SIBOL-XXX · SIBOL-NODE · http://192.168.4.1 · CODE 4821 · MQ-135 · 9 nodes
   ```

4. The OLED now shows `IP 192.168.4.1` and `CODE ####`. **Write the code down** — it is generated once from the chip's eFuse MAC and persists.

> Keep **Erase All Flash = Disabled**. Enabling it wipes LittleFS (the stored app + listings) and NVS (pairing, calibration, model).

## 4. Put the app on the node

The firmware ships with a small bootstrap page. Two ways to install the full app:

**Route A — from the node itself (no laptop tools)**

1. Join Wi-Fi `SIBOL-NODE` (open network, no password).
2. Open `http://192.168.4.1`. The bootstrap page appears.
3. Use its file picker to upload `SIBOL.html`. It is stored in LittleFS as `/index.html`.

**Route B — from the app (recommended)**

1. Open `SIBOL.html` directly in Chrome/Edge on the laptop (double-click it).
2. Join Wi-Fi `SIBOL-NODE`, then in the app: **Setup → Send app to node**.
3. Optionally **Setup → Send logo to node** so the node serves your own icon.

Both routes work offline. Route B also works from `file://` because the firmware sends `Access-Control-Allow-Origin: *`.

## 5. Pair a device

1. Join Wi-Fi **`SIBOL-NODE`**.
2. Open the app (from the node, or the local `SIBOL.html`).
3. The **Link your node** panel appears. Enter:
   - **Node address** — the `IP` line on the OLED (default `192.168.4.1`)
   - **Code** — the 4-digit `CODE` line on the OLED
   - **This device name** — e.g. `Lee-phone`
4. Press **Link node**. The OLED shows **`LINKED`** + your device name for 4 s, the LED fast-blinks, and the app pill turns green **`PAIRED`**.

The code is only ever shown on the physical OLED — being next to the node is the authorisation. The node returns a 16-hex token; the app stores it and sends it as `X-SIBOL-Token`. Read endpoints are open; **writing** (params, model, board, upload, R0 cal) requires a paired token.

Up to 8 devices pair. **Setup → Unlink** revokes the token.

### Android Wi-Fi gotchas (this is the #1 demo failure)

- Android will say *"Internet may not be available"*. Tap **Use this network anyway / Stay connected**, or it silently switches back to mobile data.
- **Turn off mobile data** during the demo.
- The captive-portal popup uses a mini-browser. For full functionality open **Chrome** and go to `http://192.168.4.1` manually.

## 7. Build the Android APK

> Arduino IDE is **only** for the firmware. The APK is a separate, one-time toolchain.

**Prerequisites (needs internet once)**

- Node.js **18+**
- JDK **17** (Temurin recommended)
- Android Studio + SDK **34**, and `ANDROID_HOME` set
- Accept licences: `sdkmanager --licenses`

**Get the builder:** open the app → **Setup → Download APK builder**. Save `build-sibol-apk.mjs` next to `SIBOL.html`.

### Build

```bash
node build-sibol-apk.mjs SIBOL.html
```

The script creates `sibol-app/`, copies the HTML to `www/index.html`, generates `manifest.webmanifest`, `sw.js`, real PNG icons (192/512/maskable/apple-touch) and `favicon.ico`, writes the Capacitor config, patches `usesCleartextTraffic="true"`, then runs Gradle.

### Output

```text
sibol-app/android/app/build/outputs/apk/debug/app-debug.apk
```

### Install

```bash
adb install -r sibol-app/android/app/build/outputs/apk/debug/app-debug.apk
```

Or copy the `.apk` to the phone and tap it (allow install from unknown sources).

### Rebuild after editing the app

Edit `SIBOL.html`, then rerun the same command. Never edit `www/` by hand.

### In the APK

The app is bundled, so it launches with no network at all. Join `SIBOL-NODE` in Android Settings, then pair with the IP + code from the OLED. Cleartext HTTP to `192.168.4.1` is explicitly permitted.

This is a debug APK — fine for sideloading and the exhibit, not for Play Store distribution.

### Laptop app (no toolchain)

**Setup → Laptop app**: download `SIBOL.ico` + `Install-SIBOL.vbs` into the same folder, run the `.vbs`. It creates a Desktop shortcut that opens the node in its own window. Linux `.desktop` and macOS `.webloc` are also provided.

### Install as a PWA

Service workers need a secure context. `http://192.168.4.1` is not one, so on the node use browser menu → **Add to Home screen**. If you serve the folder from `http://127.0.0.1` or HTTPS, the app registers `sw.js` and becomes fully installable and offline-cached.

## 8. Calibration (do this before collecting data)

1. **MQ-135 burn-in:** 24–48 h on first use. Power it and leave it. Readings before this are not stable.
2. **Warm-up:** 60 s every power-up. The OLED counts down `WARM-UP ##s`.
3. **Soil dry point:** hold the probe in air → rail → **Set dry**.
4. **Soil wet point:** immerse to the marked line in water → **Set wet**. Do not submerge the electronics.
5. **MQ divider gain:** 2.0× for 10 kΩ + 10 kΩ.
6. **Load resistor RL:** read the actual resistor on your breakout (usually 1 kΩ). Set it in the rail — Rs is computed from it.
7. **Clean-air R0:** in ventilated clean air after warm-up, press **Clean-air R0**. The node stores R0 and reports Rs/R0.
8. **Send to node** to persist parameters to NVS.

## 9. Data honesty

Every number in the app is tagged:

| Tag | Meaning |
|---|---|
| `MEASURED` | Came from the node over HTTP |
| `SIM` | Produced by the built-in simulator |
| `ESTIMATE` | Computed from a model (e.g. battery runtime) |

- The Teach tab starts with 54 `SIM` rows so the pipeline is demonstrable. They are permanently flagged. Replace them with node captures before the exhibit. Training on simulated rows and reporting the accuracy as real is falsification.
- Market prices are simulated. The board says so on its face: prices refresh randomly every 5 minutes to mimic market movement; a future version will fetch real prices from the internet. Do not present them as observed market data.
- MQ-135 output is relative millivolts, not calibrated ppm. Rs/R0 is a ratio, not a concentration.
- Battery runtime is an estimate from capacity ÷ computed draw, derated 0.8. Measure it with a meter if you want to claim it.

### Test bench

| ID | Test | Target |
|---|---|---|
| T1 | Link round-trip p95 | ≤ 250 ms |
| T2 | On-chip inference | ≤ 1000 µs |
| T3 | Held-out grade accuracy | ≥ 85 % |
| T4 | Grade-flip reduction from voting | ≥ 50 % |
| T5 | Irrigation events vs clock schedule | fewer |
| T6 | Cell runtime (heater + ESP32 budget) | ≥ 4 h |
| T7 | MQ-135 signal loss from heater undervoltage | < 5 % |

T7 is why the boost converter exists. Run it with the boost fitted and again on the raw cell — that comparison is a strong poster figure.

## 10. HTTP API

Base: `http://192.168.4.1`

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/` | — | App from LittleFS, else bootstrap page |
| GET | `/manifest.webmanifest` | — | PWA manifest |
| GET | `/logo.png` | — | Your uploaded logo |
| POST | `/api/pair` | code | `code, name` → `{ok,node,token,ip,paired}` |
| POST | `/api/unpair` | token | Revoke this token |
| GET | `/api/state` | — | Telemetry + grade + rail + Rs/R0 + heap |
| POST | `/api/cal` | token | Store current Rs as R0 |
| POST | `/api/params` | token | Form-encoded calibration / limits |
| POST | `/api/model` | token | Flat CART: `leaf,feature,thr,left,right,class;…` |
| GET | `/api/board` | — | Listings JSON |
| POST | `/api/board` | token | Replace listings JSON |
| GET | `/api/log` | — | Ring buffer as CSV (240 rows) |
| POST | `/upload` | token\* | Multipart file → LittleFS |

\* First upload is allowed unauthenticated so you can bootstrap an empty node.

CORS is `*`; `X-SIBOL-Token` is an allowed header; `OPTIONS` returns 204. Captive-portal probe paths (`/generate_204`, `/hotspot-detect.html`, `/connecttest.txt`, …) 302 to the app.

## 11. Known limits and optional hardening

| Item | Detail |
|---|---|
| **NVS size** | The model is stored as one NVS key per float. A 63-node tree = 378 keys and can overflow the default 20 KB NVS partition. Keep Teach → Detail at 3 (≤ 15 nodes). For deeper trees, store the model as a single blob string instead. |
| **Unwired BAT pin** | `batPct()` returns 100 % when the ADC reads < 1 V. If GPIO33 is not wired, the battery figure is meaningless — wire it or set Source = USB. |
| **Unwired RAIL pin** | If GPIO32 reads < 1 V the firmware assumes 5.000 V for Rs. That makes Rs/R0 an assumption, not a measurement. Wire it before claiming Rs/R0. |
| **Unwired soil probe** | GPIO35 floats and the soil feature becomes noise. The grade is then meaningless. Wire it. |
| **Grading during warm-up** | `sample()` runs inference before warm-up ends. To exclude those rows, add the guard below at the top of `sample()` after the ADC reads. |
| **Stack** | `apiModel()` allocates `float tmp[63][6]` (1512 B) on the loop-task stack. If you see resets during model upload, change it to `static float tmp[MAXN][6];`. |
| **MQ cross-sensitivity** | MQ-135 responds to alcohol, smoke, ammonia and other VOCs. It cannot identify a specific gas. No temperature/humidity compensation. |
| **Scope** | One node, small dataset. This is decision support for handlers — not a food-safety certification and not a laboratory instrument. |

**Warm-up guard** (for the *Grading during warm-up* row above):

```cpp
if (millis() < warmEnd) { stable = -1; streak = 0; return; }
```

## 12. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `redefinition of 'struct Client'` | `Client` is an abstract class in the ESP32 core. The pairing struct is named `Peer` in this sketch — do not rename it back to `Client`. |
| `expected ';' at end of input` in `drawOled()` | Truncated copy-paste. Re-copy the whole file; check the last line of `drawOled()` is `oled.display();}`. |
| `Adafruit_SSD1306.h: No such file` | Install Adafruit SSD1306 + GFX + BusIO from Library Manager. |
| Upload stalls at `Connecting.....` | Hold **BOOT** until writing begins; check the USB cable is data-capable; install CP210x/CH340 driver. |
| OLED blank | It is 128×64 at `0x3C`. Run an I²C scanner; some 0.96" modules are `0x3D`. Check SDA 21 / SCL 22. |
| App loads but every label is empty | A JS syntax error killed the script. Open DevTools → Console. All text also exists statically in the HTML, so a blank page means the file itself is truncated. |
| Node not reachable | Not on `SIBOL-NODE`; or Android switched to mobile data; or wrong IP. Re-read the OLED. |
| Wrong code | Read `CODE` from the OLED, not the serial log of a previous flash. It persists in NVS. |
| Pairing works, writes return 401 | Token was revoked or NVS was erased. Unlink and pair again. |
| Send app to node fails | Node flash is full or the file is > ~1 MB. Check Tools → Flash Size 4 MB and the spiffs partition scheme. |
| Battery always 100 % | GPIO33 divider unwired — see §11. |
| `V:--` on OLED | GPIO32 rail divider unwired — see §11. |
| Grade flickers | Raise **Votes to confirm** in the rail, raise smoothing, fit the ADC caps. |
| Random reboots on battery | No boost converter, or no 470 µF bulk cap. Wi-Fi TX bursts are browning out the LDO. |
